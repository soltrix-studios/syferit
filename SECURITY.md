# Security Policy

## Supported Versions

| Version | Supported |
| :--- | :--- |
| 1.0.x | :white_check_mark: |
| < 1.0.0 | :x: |

## Reporting a Vulnerability

The Syferit security team values the contributions of the cybersecurity and cryptography research community. If you discover a vulnerability or security flaw in Syferit's core engine, transformation primitives, or tamper traps, we appreciate your help in responsibly disclosing it to us.

### How to Report

Please do **NOT** report security issues via public GitHub Issues, discussions, or pull requests.

Instead, please send an encrypted report to:
- **Email:** `security@soltrixstudios.com`
- **Subject:** `[Security Vulnerability Report] Syferit - <Component>`

Please include in your report:
1. The package name and version affected (e.g. `@syferit/core@1.0.0`).
2. A description of the issue (e.g. mathematical reduction in an MBA identity, bypass of an anti-tamper trap).
3. A minimal reproducible proof-of-concept (PoC) script or AST representation.
4. Expected behavior vs. actual observed behavior.

### Response Timeline

- **Initial Acknowledgement:** Within 24 hours of receipt.
- **Triage & Reproduction:** Within 72 hours.
- **Remediation & Patch Release:** Vulnerability patches will be developed, tested, and released under an expedited advisory timeline.

### Safe Harbor

Soltrix Studios supports responsible security research conducted in good faith. If you conduct vulnerability research in compliance with this policy, we will not initiate legal action against you under DMCA § 1201 or computer crime statutes for activities conducted within the scope of your research.
